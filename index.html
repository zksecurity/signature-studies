BLS · Random-oracle model

BLS: reduction to co-CDH

Signing queries determine the reduction’s loss.

Adv≤C(qS)·ε
Statement & conditions

BLS.Statement.bls_eufcma_of_cocdh_machine_hardness

Finite message type; lazy random-oracle hashing; fresh-message forgery; type-3 co-CDH hardness at a budget derived from the source certificate. Repeated signing calls count toward qS. C(0) = 1.

The exact loss is C(q) = [1/(q+1) · (q/(q+1))^q]⁻¹. The source certificate also bounds hash queries, randomness, and local work.

BLS · Algebraic group model

BLS: two DLog reductions

Two DLog reductions account for both extraction branches.

Adv≤εgood+εbad+1|F|
Statement & conditions

BLS.Statement.bls_lazy_agm_of_dlog_machine_hardness

The adversary requests hash values and signatures through oracles, adapting each query to earlier replies. Hash values are sampled on first use and cached; the full hash table stays private. Its output includes coefficients over the generator and explicit hash/signature replies.

The theorem assumes finite message indices, a certificate bounding queries, local work, and coefficient sizes, and DLog hardness for two solvers at their derived machine budgets.

Good: the extraction equation has a nonzero denominator, so division recovers the discrete log. Bad: that denominator is zero; a second solver handles this branch using a known signing key and independently masked bases.

εgood and εbad bound the two solvers’ success probabilities at their respective machine budgets. The remaining extraction error contributes 1/|F|.

OOPS · Algebraic group model

OOPS: a degree-limited game

At most d distinct signed messages on the target topic.

Adv≤εgood+εbad+1|F|
Statement & conditions

OOPS.Statement.oops_lazy_agm_of_dlog_machine_hardness

Oracle-derived topic bases; finite topic type; one degree fixed for the whole game; two DLog hardness bounds at derived budgets. Freshness applies to the message/topic pair.

Repeated messages and other topics do not consume the target-topic distinct-message cap, but still count toward resource budgets. A separate call-count game comparison does not add a fifth security endpoint.

Good: the extraction equation has a nonzero denominator, so division recovers the discrete log. Bad: that denominator is zero; a second solver handles this branch using a known signing key and independently masked bases.

εgood and εbad bound the two solvers’ success probabilities at their respective machine budgets. The remaining extraction error contributes 1/|F|.

Proximity Signatures · Algebraic group model

Proximity Signatures: an extra collision term

The fresh-collision term can equal one.

Adv≤εgood+εbad+1|F|+Pr[collision]
Statement & conditions

Proximity.Statement.proximity_lazy_agm_of_dlog_machine_hardness

Oracle-derived coordinate bases; finite slot type; source certificate and two DLog hardness hypotheses. The collision event compares the fresh output vector with the signing-coefficient-weighted sum of signed vectors, including repeats and other slots.

That event does not require a valid signature, and collisions are not excluded from the original winning game. Its probability can be one.

Good: the extraction equation has a nonzero denominator, so division recovers the discrete log. Bad: that denominator is zero; a second solver handles this branch using a known signing key and independently masked bases.

εgood and εbad bound the two solvers’ success probabilities at their respective machine budgets. The remaining extraction error contributes 1/|F|.

An algebraic group model for VCVio

The AGM results above rest on agm-lean, a separate Apache-2.0 library that adds the algebraic group model to Lean 4 and VCVio. Other VCVio games can use it.

An algebraic adversary must explain every group element it sends as a combination of group elements it has already received. Having received g, X and Y, an adversary that sends a group element Z, in a query or in its final answer, also gives coefficients a, b, c with:

Z=a·g+b·X+c·Y

The library prescribes no game or oracle. Oracle replies need no explanation; they join the list of received inputs. The adversary supplies a Lean proof that its explanations hold on every possible reply path, and the library proves that running it yields valid explanations over the inputs it actually received.

Several groups can share one scalar field, as the two source groups of a pairing do. Each group element is explained only from inputs of its own group.

Key definitions

  • IsAlgebraic

    The explanation rule, required on every possible reply path.

  • Adversary

    A VCVio program paired with its proof of that rule.

  • Adversary.run

    Runs it through VCVio’s simulateQ, tracking each group’s received inputs.

  • Adversary.run_valid

    Every final explanation is valid over the inputs actually received.

The model does not bound running time or explain elements of a pairing’s target group. Games must keep every group element in the tracked group lists; group elements hidden in plain data go untracked. It starts from Fuchsbauer, Kiltz and Loss, The Algebraic Group Model and its Applications, Section 2.1.
